# 화면·데이터·예외 규칙 (자세히)

## 입력 파일에서 읽는 것

| 파일 | 시트 | 읽는 내용 |
|---|---|---|
| 결과 | `요약` | 첫 칸 제목의 기준일(`기준일 yyyy-MM-dd`), 요약 3줄, 분석 조건, 분석의 한계 |
| 결과 | `개인결과` | 분석용 ID, 등급, 점수, 본부·조직·직군·직급, 근속, 신호별 점수(`계산에 쓴 가중치 합`과 `판단불가 신호` 사이 열), 판단 근거, 추가 확인 사항, 참고 |
| 결과 | `조직결과` | 개인결과 집계와 서로 맞는지 확인하는 데만 사용 |
| 결과 | `검증`, `산정기준`, `데이터점검` | 상세 설명에 그대로 옮김 (비율 열은 %로 표시) |
| 원본 | `v_employees_current` | 기준일(`as_of`), 소속·직군·직급(연결 확인), 입사일 |
| 원본 | `개요` | 기준일 확인 (있으면) |
| 원본 | `v_attendance_monthly` | 월별 초과근무 (기준일이 속한 달까지) |
| 원본 | `hr_performance_reviews` | 기준일 이전에 확정된 평가 |
| 원본 | `hr_compensation_history` | 기준일 이전 최근 급여 변동률(`change_pct`) |
| 매핑 | `매핑` | `분석용 ID`, `사번` (연결 확인에만 사용, 출력하지 않음) |

필수 시트·열이 없으면 중단한다. 원본의 선택 시트(`hr_compensation_history`)가 없으면 인상률만 비운다.

## 원본에서 계산하는 지표

hr-risk와 같은 기준일 규칙을 쓴다.

| 지표 | 계산 |
|---|---|
| 야근 | 마지막 3개월(기준일이 월말이면 그 달까지) 중 값이 있는 달의 평균 초과근무시간. 2개월 미만이면 판단불가 |
| 평가 | 기준일 이전 최근 확정 평가(D=1 … S=5), 직전 확정 평가와 비교한 변화 |
| 인상률 | 기준일 이전 효력 시작인 급여 이력 중 `change_pct`가 있는 가장 최근 값 |
| 월간 연장근로 | 월별 1인당 평균. 그 달 값이 있는 인원이 5명 미만이면 비움 |
| 회사 전체 평균 | 기준일 재직자 전체(원본)의 평균. 필터와 무관하게 고정 |

## 입력별로 보이는 것

| 화면/항목 | 결과만 | + 원본 | + 원본 + 매핑(연결 확인됨) |
|---|---|---|---|
| 요약 | 표시 | 표시 | 표시 |
| 직원별: ID·등급·점수·판단 근거 | 표시 | 표시 | 표시 |
| 직원별: 야근·평가·인상률, 회사 평균 비교 | 이유 표시 | 이유 표시(직원 연결 안 함) | 표시 |
| 조직: 등급 분포, 점수·신호 히트맵 | 표시 | 표시 | 표시 |
| 조직: 야근·평가·인상률 열 | 이유 표시 | 부서 단위로 표시(필터 영향 없음) | 필터에 걸린 직원 기준으로 표시 |
| 월간 변화 | 이유 표시 | 표시 | 표시 |
| 상세 설명 | 표시 | 표시 | 표시 |

## 중단과 계속

| 상황 | 처리 |
|---|---|
| 결과에 `요약`/`개인결과`/`조직결과` 시트 없음, 기준일을 못 읽음 | 중단 |
| 개인결과에 `이름`·`사번`·`name`·`employee_id` 열이 있음 | 중단 |
| 분석용 ID 중복, 알 수 없는 등급 값 | 중단 |
| 원본 기준일(`as_of`, `개요`)이 결과와 다르거나 한 날짜가 아님 | 중단 |
| 출력 폴더가 스킬 폴더 안 (`-AllowSkillDir` 없음) | 중단 |
| 매핑 파일 형식·행 수·ID 중복·월 불일치 | 직원 연결 안 함(생성은 계속), 이유를 화면에 표시 |
| 소속·직군·직급 대조가 하나라도 어긋남 | 직원 연결 안 함(전부), 건수를 화면에 표시 |
| 원본 없이 매핑만 줌 | 매핑 사용 안 함, 안내 표시 |
| 개인결과와 조직결과 시트가 서로 맞지 않음 | 개인결과 기준으로 집계, 경고 표시 |
| 파일명의 월과 시트 기준일이 다름 | 시트 기준일을 따름, 경고 표시 |

## 필터가 적용되는 곳

| 화면 | 부서 | 검색(ID) | 등급 | 확인 상태 |
|---|---|---|---|---|
| 요약 | 적용(필터 N명 표시) | 적용 | 적용 | 적용 |
| 직원별 현황 | 적용 | 적용 | 적용 | 적용 |
| 조직 현황 | 적용 | 적용 | 적용 | 적용 (집계는 걸린 직원 기준으로 다시 셈, 점수·등급은 그대로) |
| 월간 변화 | 적용 | 적용 안 함 | 적용 안 함 | 적용 안 함 |

## 확인 기록 JSON

```json
{
  "schema": "hr-dashboard-notes", "version": 1,
  "baseDate": "2026-04-30", "resultFile": "퇴직위험_결과_202604.xlsx", "exportedAt": "...",
  "entries": { "R128": { "owner": "담당자", "status": "면담 예정", "next": "2026-05-20" } }
}
```

- 불러올 때 `schema`가 다르거나 `baseDate`가 다르면 거절한다(분석용 ID가 기준일마다 달라 다른 직원에게 붙을 수 있기 때문).
- 이 대시보드에 없는 분석용 ID, 허용되지 않은 상태 값·날짜 형식은 건너뛰거나 기본값으로 바꾼다.
- 기존 저장 내용을 덮어쓰기 전에 확인을 받는다.
- 저장소를 쓸 수 없는 브라우저(시크릿 창 등)에서는 경고를 띄우고, JSON 내보내기를 권한다.

## 공유용 파일에 들어가는 것

- 들어감: 기준일, 총인원, 등급별 인원, 본부·조직별 인원·평균 점수·등급 분포·신호 평균, (원본이 있으면) 부서별 야근·평가·인상률 평균과 월간 추이, 회사 전체 평균, 상세 설명.
- 안 들어감: 분석용 ID, 개인 점수·등급, 이름, 사번, 담당자·확인 상태·다음 확인일, 확인 기록 코드, 개인별 지표.
- 5명 미만 조직: 이름만 남기고 값은 null. 역산 방지를 위해 같이 가린 조직은 "보호 처리"로 표시한다.
- 공유용을 만들 때 개인결과의 직원 행은 부서 집계를 내는 데만 읽고 파일에는 쓰지 않는다. 공유용 틀과 스크립트에는 개인별 데이터를 다루는 코드가 없다.

## 디자인

차콜 블랙 테마(`assets/common.css`의 CSS 변수). 등급은 색과 함께 글자("상/중/하")를 항상 쓴다. 히트맵은 한 가지 색의 진하기와 숫자를 함께 쓴다. 폭 375px에서도 가로 스크롤 없이 읽힌다(표만 필요할 때 가로 스크롤).

## 개발 중 테스트

`test_output/`에 로컬 테스트 결과와 입력 변형(fixtures)이 있다. 합성 샘플 데이터로 만든 것이며 설치본에는 필요 없다. 테스트는 `-AllowSkillDir`로만 이 폴더에 쓴다.
