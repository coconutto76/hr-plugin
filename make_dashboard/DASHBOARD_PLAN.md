# make_dashboard 스킬 기획서

hr-risk가 만든 분석 결과를 브라우저에서 보는 대시보드로 보여 준다.

- 상태: 기획 단계. 구현하지 않았다.
- 결정은 2절에 이유와 함께 정리했다. 질문에 답해 주신 부분은 그대로, 나머지는 추천안을 적용했다.

---

## 1. 입력과 출력

| 구분 | 파일 | 비고 |
|---|---|---|
| 필수 입력 | `퇴직위험_결과_YYYYMM.xlsx` | hr-risk 결과. 이름·사번 없음, 분석용 ID만 있음 |
| 선택 입력 | `인사데이터_샘플.xlsx` (같은 기준일의 원본) | 근거 지표와 월간 추이에 필요 |
| 선택 입력 | `ID매핑_YYYYMM.xlsx` (원본과 같은 직원임을 확인하는 데 사용) | 원본을 직원별로 연결할 때만 필요. HTML에는 넣지 않음 |
| 출력 | `dashboard.html` | 내부용. 직원별(분석용 ID) 현황 포함 |
| 출력 | `dashboard_share.html` | 공유용. 부서별 요약만 포함 |

- 두 출력 모두 **외부 CDN 없이 브라우저에서 열리는 단일 HTML**이다. CSS, JS, 데이터를 파일 안에 넣는다.
- 차트는 **HTML·SVG·CSS로 직접 그린다.** 차트 라이브러리를 쓰지 않는다.
- 테마는 **차콜 블랙**이다.
- **저장 위치**: 출력 폴더의 기본값은 *현재 폴더(사용자의 작업 폴더)*이며 `-OutputDir`로 바꾼다. 설치된 스킬 폴더 안에는 쓰지 않는다(스크립트가 거절). 개발 중 로컬 테스트 결과만 `make_dashboard/test_output/`에 `-AllowSkillDir`로 저장한다.
- **구현 현황**: 구현 완료. 파일 구성과 사용법은 `SKILL.md`, 세부 규칙은 `references/screens_and_rules.md`.

## 2. 결정 사항과 이유

| # | 결정 | 이유 |
|---|---|---|
| 1 | **원본 연결**: ID매핑 파일을 세 번째 선택 입력으로 받아 연결한다. 연결 전에 소속·직급이 결과와 원본에서 같은지 대조한다 | 분석용 ID는 사번을 섞어 만든 값이라 원본에 없다. 대응표 없이는 같은 직원인지 확인할 수 없으므로 임의로 연결하지 않기 위함. 매핑은 변환에만 쓰고 HTML에는 넣지 않는다 |
| 2 | **공유 범위**: 본부 + 조직, 5명 미만 조직은 값을 파일 안 데이터에서 뺀다 | hr-risk의 조직 결과와 같은 기준. 화면에서 숨기는 것이 아니라 데이터 자체가 없어야 파일을 열어 보아도 드러나지 않는다 |
| 3 | **확인 상태**: 4단계(미확인 / 면담 예정 / 면담 완료 / 조치 불필요), 기준일별로 따로 저장 | 분석용 ID는 기준일마다 바뀌므로 다음 달 대시보드로 자동으로 이어지지 않는다. 기준일별로 나눠 저장하면 다른 달 기록이 섞이지 않는다 |
| 4 | **근거 지표**: 야근·평가·인상률 3개. 회사 전체 평균과 비교 | 점수 산정에 쓴 핵심 신호와 같은 방식으로 계산해 점수의 근거와 화면이 어긋나지 않게 한다. 6개를 모두 보이면 읽기 어렵다 |
| 5 | **차트**: HTML·SVG·CSS로 직접 구현 (질문 답변) | 외부 CDN 없이 오프라인에서도 열려야 한다 |
| 6 | **공유 파일**: 개인별 행 없이 부서별 요약만 (질문 답변) | 공유 대상에게 개인이 드러나지 않게 한다 |
| 7 | **구현 방식**: PowerShell로 HTML을 생성한다. hr-risk의 xlsx 읽기 도우미를 스킬 안에 복사해 쓴다 | Excel이 없어도 xlsx를 읽을 수 있고, hr-risk와 같은 환경에서 돌아간다. 복사하면 두 스킬이 따로 설치돼도 동작한다 |

## 3. 화면 구성

화면 순서는 요청한 그대로다.

1. **요약** — 분석 기준일, 총인원, 상/중/하 인원수. 판단불가 인원이 있으면 함께 표시한다.
2. **직원별 현황** — 분석용 ID, 등급, 점수, 판단 근거, 야근·평가·인상률과 회사 전체 평균을 나란히 보여 준다.
3. **조직 현황** — 부서별 지표 히트맵과 등급 분포.
4. **월간 변화** — 부서별 월평균 연장근로 시간 추이(회사 전체 선 포함).
5. **상세 설명** — 가설, 검증 결과, 분석 한계. **기본은 접힌 상태.** 결과 파일의 `요약`·`검증`·`산정기준` 내용을 쓴다.

### 어떤 입력이 있어야 보이는가

| 화면/항목 | 결과만 | + 원본 | + 원본 + ID매핑 |
|---|---|---|---|
| 1 요약 | 표시 | 표시 | 표시 |
| 2 분석용 ID·등급·점수·신호 점수·판단 근거 | 표시 | 표시 | 표시 |
| 2 야근·평가·인상률 실제 값, 회사 평균 비교 | 이유 표시 | 이유 표시 (직원 연결 불가) | 표시 |
| 3 등급 분포, 평균 점수·상 비율·신호별 평균 점수 히트맵 | 표시 | 표시 | 표시 |
| 3 원본 지표 열(월평균 연장근로, 평균 인상률, 평균 평가) | 이유 표시 | 표시 | 표시 |
| 4 월간 변화 | 이유 표시 (월별 자료는 원본에만 있음) | 표시 | 표시 |
| 5 상세 설명 | 표시 | 표시 | 표시 |

표시할 수 없는 곳에는 빈 칸 대신 "원본 인사데이터가 없어 표시할 수 없습니다" 같은 이유를 화면에 쓴다. 원본은 있으나 직원 연결을 확인하지 못했다면 "ID매핑 파일이 없거나 소속·직급 대조가 맞지 않아 직원별로 연결하지 않았습니다"라고 쓴다.

## 4. 기능

### 4.1 필터

- 부서(본부 → 조직), 검색(분석용 ID 부분 일치), 등급, 확인 상태.
- 필터는 관련된 화면에 함께 적용한다.

| 화면 | 적용 |
|---|---|
| 요약 | 전체 총계는 고정, 필터에 걸린 인원수를 함께 표시 |
| 직원별 현황 | 네 필터 모두 |
| 조직 현황 | 네 필터 모두. 집계는 필터에 걸린 직원 기준으로 다시 세고, 화면에 "필터 적용: N명"을 표시 |
| 월간 변화 | 부서 필터만. 등급·검색·확인 상태는 직원 연결이 필요하고 작은 집단에서 개인이 드러날 수 있으므로 적용하지 않고, 그 이유를 표시 |

### 4.2 점수 표시 원칙

- 점수는 **퇴사 확률이 아니라 먼저 확인할 대상을 정하는 지표**다. 화면 머리말에 문구를 둔다.
- **필터를 바꿔도 직원 개인의 점수·등급은 결과 파일 값 그대로이며 다시 계산하지 않는다.** 조직 집계는 필터에 걸린 인원을 다시 세는 것이지 점수를 새로 매기는 것이 아니다.
- "회사 전체 평균"은 기준일 재직자 전체의 값으로 고정한다. 필터를 바꿔도 변하지 않는다.

### 4.3 확인 관리

- 담당자, 확인 상태(4단계), 다음 확인일을 **분석용 ID에 연결**해 브라우저(localStorage)에 저장한다.
- 저장 키에 기준일과 결과 파일 이름을 넣어 기준일별로 분리한다.
- JSON으로 **내보내기/불러오기**를 제공한다. 불러올 때 기준일이 다르면 거절하고, 현재 기록을 덮어쓰기 전에 확인을 받는다.
- "브라우저 메모"는 담당자·확인 상태·다음 확인일 3개 항목으로 구현했다. 자유 입력 메모란은 만들지 않았다(요청한 항목만 둠). 담당자 이름이 들어 있으므로 내보낸 JSON은 내부 파일로 다루라고 화면에 안내한다.
- 저장은 그 브라우저에만 남는다. 다른 사람과 공유하려면 JSON을 내보내야 한다는 점을 화면에 쓴다.

## 5. 데이터 규칙

### 5.1 기준일 확인

원본이 제공되면 결과의 기준일과 원본의 기준일(`개요`/`as_of`)이 같은지 확인한다. **다르면 생성을 멈추고 알린다.** ID매핑 파일을 쓰면 그 파일의 기준 월(파일명 YYYYMM)도 결과와 같은지 확인한다.

### 5.2 직원 연결 (분석용 ID 기준)

1. 매핑 파일의 행 수가 결과의 `개인결과` 행 수와 같고, 분석용 ID가 중복되지 않는지 확인한다.
2. 매핑의 사번이 모두 원본 `v_employees_current`에 있는지 확인한다.
3. 각 분석용 ID마다 결과의 본부·조직·직군·직급이 원본과 같은지 대조한다.
4. 하나라도 어긋나면 **직원별 연결을 전부 하지 않는다**(일부만 연결하면 어느 쪽이 맞는지 알 수 없다). 불일치 건수와 함께 이유를 화면에 쓴다. 생성은 계속한다.
5. 연결이 끝나면 사번은 버린다. HTML과 중간 파일에 사번과 매핑을 남기지 않는다.

### 5.3 원본에서 계산하는 지표

hr-risk와 같은 기준일 규칙을 쓴다. 기준일 이후 기록은 원본에서도 쓰지 않는다.

| 지표 | 계산 |
|---|---|
| 야근 | 최근 3개월 평균 월 초과근무시간. 기준일이 속한 달이 마지막 달 |
| 평가 | 기준일 이전 최근 확정 평가(S=5…D=1)와 직전 평가 대비 변화 |
| 인상률 | 기준일 이전 최근 급여 변동률(`change_pct`) |
| 월간 연장근로 | 부서별 1인당 월평균 초과근무시간, 기준일이 속한 달까지 가용한 모든 월(샘플은 2025-05~2026-04, 12개월) |

- 월간 변화는 본부별 선을 기본으로 하고 조직을 선택할 수 있다. 5명 미만 조직은 제외한다. 회사 전체 선을 함께 그린다.
- 값이 없는 직원·월은 0으로 채우지 않고 비워 둔다.

### 5.4 공유용 파일의 데이터

- 포함: 기준일, 총인원, 본부·조직별 등급 인원수, 평균 점수, 신호별 평균 점수, (원본이 있으면) 월간 연장근로 추이, 상세 설명(가설·검증·한계).
- 제외: 분석용 ID, 개별 점수·등급, 이름, 사번, 담당자, 확인 상태, 다음 확인일, 개인 메모, 확인 관리 기능 코드.
- 5명 미만 조직은 '표본 부족'만 남기고 평균·분포·추이 값을 데이터에 넣지 않는다.
- 공유용 파일은 **집계 값만 별도 구조로 만들어** 넣는다. 부서 집계를 내려면 생성 과정에서 개인결과 행을 읽어야 하지만 파일에는 쓰지 않으며, 공유용 틀·스크립트에는 개인별 데이터를 다루는 코드가 없다. (초안의 "개인 데이터를 읽지도 않고"는 부서별 신호 평균을 내려면 지킬 수 없어 이렇게 바로잡았다.)
- 5명 미만 조직을 빼고 남은 합계에서 역산되지 않도록, 가려진 인원이 5명 미만이면 가장 작은 다른 조직도 함께 가린다("보호 처리").

## 5-1. 생성 후 열기

- 생성이 끝나면 `dashboard.html`을 연다(내장 브라우저 → `-Open`으로 기본 브라우저 순서).
- 실행 환경에서 열 수 없으면(원격 실행, 브라우저 없음 등) **파일의 전체 경로와 여는 방법**(더블클릭, 브라우저에 끌어다 놓기, 주소창에 `file:///` 주소 붙여 넣기)을 안내한다. 스크립트가 항상 이 안내와 주소를 출력한다.
- `dashboard_share.html`은 자동으로 열지 않고 경로만 알린다.

## 6. 디자인 (차콜 블랙)

- 배경 `#14161a`, 패널 `#1c1f24`, 선 `#2f343c`, 글자 `#e6e8eb`, 보조 글자 `#9aa1ab`. 색은 CSS 변수 한 곳에 둔다.
- 등급 색은 상 붉은 계열, 중 노란 계열, 하 초록 계열이되 **색만으로 구분하지 않고** 글자("상/중/하")를 항상 함께 쓴다.
- 히트맵은 한 가지 색의 진하기로 값을 나타내고 칸 안에 숫자를 쓴다.
- 폭 360px 정도의 좁은 화면에서도 가로 스크롤 없이 읽히게 한다. 표는 필요할 때만 가로로 스크롤한다.
- 글자 대비는 어두운 배경 기준으로 충분히 확보한다.

## 7. 스킬 구조 (예정)

```
make_dashboard/
├── SKILL.md
├── DASHBOARD_PLAN.md
├── scripts/
│   ├── build_dashboard.ps1     결과·원본·매핑 읽기, 검증, HTML 생성
│   └── lib_xlsx.ps1            hr-risk의 읽기 도우미 복사본
├── assets/
│   ├── dashboard.template.html 내부용 틀 (CSS·JS 포함)
│   └── share.template.html     공유용 틀 (개인 데이터를 다루는 코드 없음)
└── references/                 입력 조건, 화면·기능 명세, 검증 기준
```

실행은 `build_dashboard.ps1 -ResultPath <결과.xlsx> [-SourcePath <원본.xlsx>] [-MappingPath <ID매핑.xlsx>] [-OutputDir <폴더>]` 형태로 한다. 스크립트가 자기 위치를 기준으로 보조 파일을 찾으므로 설치 위치가 바뀌어도 동작한다.

## 8. 만든 뒤 확인할 것

1. **공유용 누출 검사**: `dashboard_share.html` 전체에서 분석용 ID 형태(`R` + 숫자 3자리), 사번 형태(7자리 숫자), 원본의 이름 목록, 담당자·확인 상태 관련 문자열이 한 건도 나오지 않는다.
2. **5명 미만 조직**: 공유용 데이터에 그 조직의 수치가 없다(작은 조직이 있는 테스트 입력으로 확인).
3. **점수 불변**: 필터를 여러 번 바꿔도 직원 점수·등급이 결과 파일 값과 같다.
4. **기준일 불일치**: 다른 기준일의 원본을 넣으면 생성이 멈추고 파일이 만들어지지 않는다.
5. **연결 불일치**: 소속이 하나라도 다른 매핑을 넣으면 직원별 연결을 하지 않고 이유가 화면에 보인다.
6. **원본 없음**: 필요한 화면마다 이유가 보이고 오류가 나지 않는다.
7. **외부 호출 없음**: `http://`·`https://` 주소가 파일에 없다(SVG 네임스페이스 문자열은 요청이 아니므로 예외로 허용하고 목록에 적어 둔다).
8. **확인 관리**: 저장 → 새로고침 → 유지, 내보내기 → 비우기 → 불러오기, 다른 기준일 JSON 거절.
9. **상세 설명 접힘**: 처음 열었을 때 접혀 있다.

## 9. 알아 둘 점

- 분석용 ID는 기준일마다 바뀌어서 지난달 확인 기록은 다음 달 대시보드로 이어지지 않는다. 필요하면 JSON을 보관해 두고 참고하는 용도로만 쓴다.
- 직원별 현황이 들어 있는 `dashboard.html`은 분석용 ID와 소속·직급이 있어 HR 내부용이다. 공유가 필요하면 `dashboard_share.html`만 쓴다.
- 샘플은 합성 데이터이고 퇴사 건수가 적어(22건) 예측 성능을 확인할 수 없다. 이 한계는 상세 설명에 그대로 옮긴다.
