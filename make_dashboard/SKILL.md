# make_dashboard: HR 위험 신호 대시보드

hr-risk 결과 엑셀을 **외부 주소 없이 열리는 단일 HTML 두 개**로 바꾼다.

- `dashboard.html` — 내부용. 분석용 ID별 현황과 확인 기록 기능이 있다. HR 담당자만 본다.
- `dashboard_share.html` — 공유용. **부서별 요약만** 있다. 개인별 행·이름·사번·개인 메모(담당자·확인 상태·다음 확인일)는 화면에서만 숨긴 것이 아니라 **파일 안의 내부 데이터에도 남기지 않는다.**

점수는 퇴사 확률이 아니라 먼저 확인할 대상을 정하는 지표다. 이 문구가 두 화면 맨 위에 들어가고, 필터를 바꿔도 개인의 점수와 등급은 다시 계산하지 않는다.

## 스킬 폴더와 경로

이 SKILL.md가 있는 폴더가 **스킬 폴더**다(스킬이 로드될 때 알려 주는 Base directory). 스크립트는 자기 위치를 기준으로 `assets/`를 찾으므로 어디에 설치돼도 동작한다. 아래 명령의 `<스킬 폴더>`를 실제 경로로 바꿔 쓴다.

```
make_dashboard/
├── SKILL.md
├── DASHBOARD_PLAN.md              기획서
├── scripts/build_dashboard.ps1    생성 본체
├── scripts/check_share.ps1        공유용 파일 개인정보 검사
├── scripts/lib_xlsx.ps1           엑셀 읽기 (Excel 없이 동작)
├── assets/                        HTML 틀, CSS, JS (생성 시 파일 안에 합쳐 넣음)
├── references/screens_and_rules.md  화면·기능·예외 규칙 자세히
└── test_output/                   개발 중 로컬 테스트 결과 (설치본에는 필요 없음)
```

## 입력

| 구분 | 파일 | 없으면 |
|---|---|---|
| 필수 | `퇴직위험_결과_YYYYMM.xlsx` (hr-risk 결과) | 만들 수 없음 |
| 선택 | 같은 기준일의 원본 `인사데이터_샘플.xlsx` | 야근·평가·인상률 값, 회사 평균 비교, 월간 변화는 "원본이 없어 표시할 수 없다"는 이유가 화면에 표시됨. 나머지는 모두 표시 |
| 선택 | `ID매핑_YYYYMM.xlsx` (원본과 같은 직원임을 확인하는 데만 사용) | 원본을 직원별로 연결하지 않음. 부서 단위 원본 지표는 표시 |

- 결과 파일만으로도 요약, 직원별 점수·근거, 조직 히트맵, 등급 분포, 상세 설명이 모두 나온다.
- 입력 파일을 사용자가 말하지 않았으면 작업 폴더에서 `퇴직위험_결과_*.xlsx`를 찾고, 여러 개면 어느 것인지 묻는다. 원본이 있으면 쓸지 물어본다.
- **ID매핑 파일은 HR 전용이므로 직접 찾아 나서지 않는다.** 사용자가 경로를 줄 때만 쓰고, 직원별 지표를 보고 싶다고 하면 그 경로를 묻는다.

## 출력과 저장 위치

- 파일: `dashboard.html`, `dashboard_share.html` (두 개 모두 UTF-8 단일 HTML).
- **사용자의 작업 폴더에 저장한다.** `-OutputDir`을 주지 않으면 *현재 폴더*에 쓰므로, 반드시 사용자의 작업 폴더에서 실행하거나 `-OutputDir`로 작업 폴더를 지정한다.
- **설치된 스킬(플러그인) 폴더 안에는 결과를 쓰지 않는다.** 출력 폴더가 스킬 폴더 안이면 스크립트가 중단한다. 개발 중 로컬 테스트만 `-AllowSkillDir`로 `test_output/`에 쓴다(사용자 요청에는 이 옵션을 쓰지 않는다).

## 실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬 폴더>\scripts\build_dashboard.ps1" `
  -ResultPath "<작업 폴더>\퇴직위험_결과_202604.xlsx" `
  [-SourcePath "<작업 폴더>\인사데이터_샘플.xlsx"] `
  [-MappingPath "<ID매핑_202604.xlsx 경로>"] `
  [-OutputDir "<작업 폴더>"]
```

종료 코드 2는 입력 문제로 **중단**한 것이다(파일을 만들지 않음). 콘솔의 중단 사유를 그대로 사용자에게 전한다(예: 결과와 원본의 기준일이 다르면 두 날짜를 알려 주고 같은 기준일의 원본을 받아 오게 한다). 생성 후에는 `dashboard.html`을 열고 공유 파일을 검사한다.

### 생성 후 열기

생성이 끝나면 `dashboard.html`을 연다. 실행 환경에서 쓸 수 있는 방법을 순서대로 시도한다.

1. 앱에 내장 브라우저(미리보기)가 있으면 `file:///` 주소로 연다(스크립트가 마지막 줄 근처에 주소를 출력한다). 열린 뒤 요약 타일과 표가 그려졌는지, 콘솔 오류가 없는지 확인한다.
2. 내장 브라우저가 없으면 스크립트에 `-Open`을 붙여 사용자의 기본 브라우저로 연다.
3. **둘 다 안 되면**(원격·클라우드 실행, 브라우저 없음, 권한 거절 등) 억지로 시도하지 말고 **파일의 전체 경로와 여는 방법**을 알려 준다: "탐색기에서 `dashboard.html`을 더블클릭하거나, 브라우저(Chrome·Edge)에 파일을 끌어다 놓거나, 주소창에 `file:///` 주소를 붙여 넣으세요."
4. `dashboard_share.html`은 자동으로 열지 않는다. 경로만 알리고, 공유하기 전에 `check_share.ps1`로 검사했다고 말한다.

미리보기 창이 브라우저 저장소를 막으면 "저장할 수 없다"는 경고가 보이는데, 일반 브라우저에서는 저장된다. 이 경우 확인 기록 저장은 미리보기에서 시험하지 못했다고 사실대로 전한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬 폴더>\scripts\check_share.ps1" -SharePath "<작업 폴더>\dashboard_share.html" [-SourcePath "<원본.xlsx>"]
```

`통과`가 나와야 공유해도 된다고 알린다. 원본을 쓰지 않았으면 이름·사번 대조는 하지 않았다고 함께 말한다.

## 화면 (순서 고정)

1. **요약** — 분석 기준일, 총인원, 상/중/하 인원수(판단불가가 있으면 함께). 필터를 걸면 "필터 N명"이 함께 나온다.
2. **직원별 현황** — 분석용 ID, 등급, 점수, 소속, 야근·평가·인상률과 회사 전체 평균, 판단 근거(행을 누르면 펼침). *내부용에만 있다.*
3. **조직 현황** — 부서별 지표 히트맵, 등급 분포.
4. **월간 변화** — 부서별 월평균 연장근로 시간 추이(회사 전체 선 포함).
5. **상세 설명** — 가설, 검증 결과, 분석 한계. **기본은 접힌 상태.**

### 필터와 확인 기록 (내부용)

- 부서·검색(분석용 ID)·등급·확인 상태 필터가 요약·직원별·조직 현황에 함께 적용된다. 월간 변화에는 부서 필터만 적용된다(나머지는 작은 집단에서 개인이 드러날 수 있어 적용하지 않고 이유를 화면에 표시).
- 담당자·확인 상태(미확인/면담 예정/면담 완료/조치 불필요)·다음 확인일을 분석용 ID별로 입력하면 이 브라우저(localStorage)에 기준일별로 저장된다. **JSON 내보내기/불러오기**로 옮길 수 있고, 기준일이 다른 파일은 불러오지 않는다.
- 분석용 ID는 기준일마다 바뀌므로 지난달 확인 기록은 다음 달 대시보드로 이어지지 않는다는 점을 사용자에게 알린다. 담당자 이름이 든 JSON은 내부 파일로 다루게 한다.

## 반드시 지킬 규칙

이유와 함께 지킨다. 이 도구는 사람을 점수로 다루므로 잘못 쓰이거나 개인이 드러나는 일을 막는 것이 우선이다.

- **기준일이 다르면 생성을 멈춘다.** 원본의 기준일(`개요`·`as_of`)이 결과의 기준일과 다르면 스크립트가 중단한다. 날짜를 고쳐 억지로 맞추지 않는다. 같은 기준일의 원본을 받아 오게 한다.
- **직원 연결은 분석용 ID로 먼저 확인하고, 확인할 수 없으면 연결하지 않는다.** 매핑의 행 수·ID 중복·사번 존재·월(파일명)을 확인하고, 모든 분석용 ID의 본부·조직·직군·직급이 결과와 원본에서 같을 때만 연결한다. 하나라도 어긋나면 *전부* 연결하지 않고 이유를 화면에 쓴다(일부만 연결하면 어느 쪽이 맞는지 알 수 없다). 매핑·사번은 변환에만 쓰고 HTML에 넣지 않는다. 이름·이름 순서 같은 다른 단서로 임의 연결하지 않는다.
- **공유용은 개인별 데이터를 파일에 넣지 않는다.** 5명 미만 조직은 값 자체를 뺀다. 그 조직을 빼고 남은 합계로 역산되지 않도록, 가려진 인원이 5명 미만이면 다른 조직도 함께 가린다(화면에 "보호 처리"로 표시). 월 인원이 5명 미만인 달도 비운다.
- **필터는 결과 파일의 값을 걸러서 보여 줄 뿐, 점수·등급을 다시 계산하지 않는다.** 필터를 바꿔도 개인의 점수·등급은 결과 파일 값 그대로다. 조직 집계는 필터에 걸린 직원을 다시 세는 것일 뿐이고, 회사 전체 평균은 고정이다.
- **점수를 퇴사 확률처럼 말하지 않는다.** 예측 성능을 확인할 수 없다는 한계(사건 수·기준일 1개)를 상세 설명에서 지우지 않는다.
- **이름·사번이 든 결과 파일은 거절한다.** 개인결과에 `이름`·`사번` 열이 있으면 중단한다.
- **원본이 없어 표시할 수 없는 화면에는 빈 칸 대신 이유를 쓴다.**
- 기준일 이후 기록은 원본에서도 쓰지 않는다(근태는 기준일이 속한 달까지, 평가는 기준일 이전 확정분, 인상률은 기준일 이전 변동).
- 외부 주소를 부르지 않는다. 차트는 SVG·HTML·CSS로 직접 그리고 파일 안에 모두 들어 있다.

## 사용자에게 전할 내용

1. 만든 파일 두 개의 위치와 용도(내부용/공유용), `dashboard.html`을 열었는지(못 열었으면 경로와 여는 방법).
2. 원본·직원 연결 상태(연결됨 / 연결 안 함과 그 이유).
3. 콘솔의 경고(기준일 이후 제외 건수, 연결 불일치, 조직결과와 개인결과 불일치 등).
4. 공유 파일 검사 결과.
5. 분석의 한계와 점수의 의미(퇴사 확률 아님).

자세한 화면·데이터·예외 규칙은 `references/screens_and_rules.md`에 있다.
