# 점수 산정과 검증 기준

설정값은 모두 `config/risk_config.json`에 있다. 아래 숫자는 지금 설정값이며, 초기값(가안)이다.

## 왜 규칙 기반 점수인가

- 샘플 규모는 186명, 목표 사건(90일 이내 자발적 퇴사)은 22건이다. 통계 모델을 학습하면 과적합 위험이 크고, 이유를 설명하기 어렵다.
- 규칙 점수는 신호별로 "왜 이 사람이 올라왔는지"를 보여줄 수 있어 면담·업무량 점검으로 바로 이어진다.
- 퇴사라벨은 점수 계산에 쓰지 않는다. 사후 점검에만 쓴다.

## 신호와 가중치

| 신호 | 가중치 | 계산 | 점수 |
|---|---|---|---|
| 초과근무 증가 | 35 | 최근 3개월 평균 − 직전 3개월 평균(월 초과근무시간). 각 구간 2개월 이상 필요. 증가 4시간 이상이면 1 | 0~1 |
| 평가 변화 | 30 | 최근 확정 평가 vs 직전 확정 평가(D<C<B<A<S). 2단계 이상 하락 1.0, 1단계 하락 0.7, 같은 등급이 C 이하이면 0.4, 그 밖에 0 | 0~1 |
| 근속 구간 | 20 | 1년 미만 0.4 / 1~3년 1.0 / 3~5년 0.4 / 5~10년 0.3 / 10년 이상 0.1 | 구간별 |
| 연차 소진 낮음 | 5 | 연차 사용/부여 < 0.10 → 1, < 0.20 → 0.5, 그 밖에 0 | 0~1 |
| 승진 보류 | 5 | 최근 24개월 안에 승진 심사 결과가 보류 → 1 | 0 또는 1 |
| 급여 밴드 하단 | 5 | 급여가 밴드 범위의 중간보다 낮을수록 높음(최하단 1) | 0~1 |

- 근속 구간의 방향(1~3년이 가장 높음)은 가설이다. 데이터를 보고 맞춘 값이 아니다.
- 초과근무 증가 상한(4시간), 연차 소진 경계는 점수 분포를 보고 정한 초기값이다.

## 점수 환산과 등급

```
점수 = Σ(가중치 × 신호 점수) / Σ(계산 가능한 신호의 가중치) × 100
```

- 계산 못 한 신호(판단불가)는 분모에서도 뺀다. 입사한 지 얼마 안 돼 근태·평가가 적은 직원이 자동으로 낮은 점수를 받지 않게 하기 위함이다.
- 계산 가능한 가중치 합이 50 미만이면 **점수와 등급을 매기지 않고 `판단불가`로 둔다**. 근속과 보조 신호만으로는 순서를 정할 근거가 약하기 때문이다.
- 등급은 고정 점수 구간이다: **상 ≥ 50, 중 ≥ 30, 하 < 30**. 고정 구간은 매월 비교할 수 있고, 위험한 사람이 없는 달에 억지로 '상'이 생기지 않는다.
- 상대 비율(상위 10% 등)은 쓰지 않는다.
- 신호 점수가 0.5 이상이면 "신호 있음"으로 보고 `판단 근거`에 쓰고 `추가 확인 사항`을 붙인다.

## 조직 결과

본부·조직별 인원, 평균 점수, 등급별 인원, 가장 많은 신호를 낸다. 조직 인원이 5명 미만이면 '표본 부족'으로 표시하고 수치를 숨긴다. 개인이 드러나기 때문이다. "가장 많은 신호"와 요약의 "많이 나타난 신호"에서 근속 구간은 뺀다(모든 직원에게 값이 있는 프로필 성격이라 순위에 의미가 없다).

## 기준일 이후 정보 제외

점수 계산 전에 아래를 모두 걸러낸다. 걸러낸 건수는 `데이터점검`과 `검증 3`에 남긴다.

| 데이터 | 기준 |
|---|---|
| 근태 | `pay_month`가 사용 가능한 마지막 월(기준일이 속한 월 또는 직전 월) 이후 |
| 평가 | 확정일(`finalized_at`)이 기준일 이후, 또는 미확정 |
| 보상 이력 | 시작일(`effective_from`)이 기준일 이후 |
| 승진 심사 | 결정일(`decided_at`)이 기준일 이후 |
| 인사발령 | 점수에 쓰지 않음. 기준일 이후 기록(퇴사 포함)은 건수만 센다 |
| 퇴사라벨 | 점수에 쓰지 않음. 4단계 사후 점검에서만 사용 |

`v_employees_current`의 `last_rating`은 기준일 이전 최신 확정 평가와 같다는 것을 샘플에서 확인했다(186명 모두 일치). 점수에는 쓰지 않고 평가 이력에서 다시 계산한다.

## 점수에서 제외하는 정보

이름, 사번, 병가(`sick_days`), 설문 응답·미응답, 성별, 나이·생년월일, 혼인 여부, 국적, 거주지, 퇴사라벨. 앞의 여섯은 요구사항이다. 나머지 세 항목(혼인·국적·거주지)은 민감 정보이거나 성별·나이를 대신하는 변수가 될 수 있어 추가로 제외했다.

## 검증 기준 (결과 `검증` 시트)

1. **등급별 실제 결과** — 상/중/하/판단불가별로 90일 이내 자발적 퇴사 건수·비율, 180일 이내 퇴사(유형 불문, 참고) 건수·비율.
2. **신호별 반례** — "신호 있음/없음" 집단별 퇴사 비율, 반례 A(신호 있는데 퇴사 안 함), 반례 B(신호 없는데 퇴사), 판단불가 인원.
3. **기준일 이후 정보 사용 여부** — 제외한 행 수.
4. **분석의 한계** — 항상 다음을 적는다.
   - 점수는 퇴사 확률이 아니라 확인 순서 지표다.
   - 자발적 퇴사 건수와 기준일이 하나라 시간 흐름에 따른 검증을 할 수 없으므로 **예측 성능을 확인할 수 없다**. 퇴사 이력이 없으면 "퇴사 이력이 없어" 확인할 수 없다고 적는다.
   - 퇴사 건수가 30건 미만이면 사후 점검 비율은 우연의 영향이 크다(참고용).
   - 입력에 없는 사정(개인 사유, 외부 제안 등)은 반영하지 못한다.
   - 유지 우선순위는 위험 점수와 별도로 HR이 판단한다. 점수에는 핵심 인재 여부·성과 가치를 넣지 않고, 점수와 합친 순위도 만들지 않는다.

사후 점검 결과가 기대와 다르면(예: 상 등급의 실제 퇴사 비율이 낮음) 그대로 보고한다. 퇴사라벨에 맞춰 가중치·경계를 고치면 우연에 맞춘 점수가 되므로 하지 않는다.

## 설정 키

| 키 | 의미 |
|---|---|
| `weights.*` | 신호별 가중치 |
| `min_available_weight` | 점수를 매기는 데 필요한 계산 가능 가중치 합 |
| `grade_cutoffs.high/mid` | 상/중 경계 |
| `flag_threshold` | "신호 있음" 기준 |
| `min_group_size` | 조직 결과를 보여 주는 최소 인원 |
| `min_events_for_validation` | 사후 점검을 참고 이상으로 볼 최소 퇴사 건수 |
| `overtime.*` | 비교 구간 길이, 구간별 최소 월 수, 증가 상한 |
| `rating.*` | 등급 순서, 하락 점수, 정체 기준 |
| `tenure_bins` | 근속 구간 경계(`upto`, 년)와 점수 |
| `leave_use`, `promotion_hold`, `pay_band` | 보조 신호 기준 |
| `actions.*` | 신호별 추가 확인 문구 |
