# hr-risk: HR 위험 신호 검토

HR 담당자가 매월 초 인사데이터 엑셀을 넣으면, 기준일 재직자의 위험 신호를 **상/중/하**로 정리해 결과 엑셀과 요약 3줄을 돌려준다. 점수는 *누구부터 살펴볼지 정하는 순서 지표*이고, 퇴사 확률도 인사 결정의 근거도 아니다. 이 점을 결과를 전할 때마다 분명히 한다.

## 스킬 폴더와 경로

이 SKILL.md가 있는 폴더가 **스킬 폴더**다. 스크립트·설정·참고 문서는 모두 이 폴더 안에 있고, 스크립트는 자기 위치를 기준으로 보조 파일을 찾으므로 스킬 폴더를 어디에 두어도 동작한다.

```
hr-risk/
├── SKILL.md
├── config/risk_config.json        가중치, 등급 경계, 최소 인원 등 설정 한 곳
├── scripts/run_hr_risk.ps1        분석 본체 (PowerShell)
├── scripts/lib_xlsx.ps1           엑셀 읽기 (Excel 없이 파일 구조를 직접 읽음)
├── scripts/lib_excel_out.ps1      결과 엑셀 쓰기 (Excel COM)
└── references/                    입력 조건, 점수·검증 기준, 출력 양식
```

아래 명령의 `<스킬 폴더>`는 이 파일이 있는 폴더의 실제 경로로 바꿔 쓴다.

## 실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬 폴더>\scripts\run_hr_risk.ps1" -InputPath "<인사데이터_샘플.xlsx 경로>"
```

선택 인자: `-BaseDate yyyy-MM-dd`(기준일 직접 지정), `-OutputDir`(결과 폴더, 기본은 입력 파일 폴더), `-MappingDir`(ID 매핑 파일 폴더, 기본은 결과 폴더), `-ConfigPath`.

- 입력 파일을 따로 말하지 않으면 현재 작업 폴더의 `인사데이터_샘플.xlsx`를 쓴다.
- 기준일은 파일의 `개요` 시트와 `v_employees_current.as_of`에서 읽는다. 둘이 다르면 스크립트가 멈춘다. 사용자가 기준일을 말했을 때만 `-BaseDate`를 준다.
- 결과 엑셀은 Excel COM으로 만들므로 **Excel이 설치된 Windows PC**에서만 실행된다. Excel을 못 띄우면 오류 메시지를 그대로 전하고, 다른 방법으로 결과를 꾸며 내지 않는다.
- 실행에 1~2분 걸릴 수 있다. 종료 코드 2는 입력 문제로 **중단**한 것이다(결과 파일 없음). 콘솔에 나온 중단 사유를 사용자에게 전해 입력을 고치게 한다.

## 분석 6단계

스크립트가 2~4단계를 자동으로 수행하고, 사용자에게 전하는 일은 1·5·6단계에서 한다. 각 단계의 세부 기준은 `references/`에 있다.

1. **질문** — 분석 대상은 기준일 재직자, 사건은 *기준일 이후 90일 이내 자발적 퇴사*(180일은 참고용). 사용자가 다른 기준일·기간을 원하면 그 점을 먼저 확인한다. 계약만료·비자발적 퇴사는 사건이 아니다(계약 만료 예정자는 `참고` 열에 따로 표시).
2. **데이터** — 입사 기록, 근태, 평가 이력의 의미와 누락·중복을 점검한다. 사번 중복·기준일 불일치처럼 결과가 틀어지는 문제는 **중단**, 일부 월/평가 누락은 해당 신호만 **판단불가**로 표시하고 진행한다. 결과는 `데이터점검` 시트에 남는다. (`references/input_spec.md`)
3. **가설** — 초과근무 증가, 평가 변화, 근속 구간이 위험 신호와 관련 있다고 보고 점수에 반영한다. 보조로 연차 소진, 승진 보류, 급여 밴드 위치를 쓴다. (`references/scoring_and_validation.md`)
4. **검증** — 기준일 이후 정보를 쓰지 않았는지, 신호별 반례(신호가 있는데 퇴사 안 한 사람, 신호가 없는데 퇴사한 사람)가 얼마나 되는지, 등급별 실제 결과가 어떤지를 `검증` 시트에 넣는다. 점수 산정 방식과 한계도 여기에 적는다.
5. **행동** — 신호별 추가 확인 사항(업무량 점검, 면담, 성장 기회 논의 등)을 `개인결과`에 붙인다. 이것은 *확인 제안*이다. 유지 우선순위는 위험 점수와 별도로 HR이 판단한다.
6. **재사용** — 입력 조건, 분석 절차, 검증 기준, 출력 양식이 `references/`와 `config/`에 정리돼 있다. 다음 달에는 같은 명령에 새 파일만 넣으면 된다.

## 반드시 지킬 규칙

이 규칙들은 사람을 점수로 평가하는 도구가 오남용되거나 새 정보로 오염되는 것을 막기 위한 것이다. 이유와 함께 지킨다.

- **이름·사번은 결과에 넣지 않는다.** 행은 분석용 ID(`R001`…)로 구분한다. 사번은 기준일을 씨앗으로 섞어 번호를 매기므로 같은 입력이면 같은 ID가 나오고, 사번 순서는 드러나지 않는다. ID↔사번 대응표는 결과와 **분리된 `ID매핑_YYYYMM.xlsx`**에만 있고 HR만 보관해야 한다. 이 파일을 결과 파일과 같이 공유하지 말라고 사용자에게 알린다. 대화에서도 이름·사번을 입력 파일에서 꺼내 쓰지 않는다.
- **점수 산정에서 제외한다**: 이름, 사번, 병가, 설문 응답·미응답, 성별, 나이(생년월일), 혼인 여부, 국적, 거주지, 퇴사라벨. 앞의 여섯은 요구사항이고, 혼인·국적·거주지는 민감 정보이거나 성별·나이를 대신하는 변수가 될 수 있어 추가로 제외했다.
- **기준일 이후에 생긴 정보는 분석 입력에서 제외한다.** 그중에서도 **기준일 이후의 퇴사일**(인사발령의 퇴사 기록, 퇴사라벨의 `left_date`)과 **기준일 이후에 확정된 평가 기록**이 점수로 새면 결과가 답을 미리 알고 만든 것이 되므로 가장 조심한다. 근태(기준일 이후 월), 보상·승진 기록도 같다. 몇 건을 뺐는지 `데이터점검`·`검증` 시트에 남는다. 샘플에는 기준일 이후 근태 532행, 평가 161건, 인사발령(퇴사) 58건이 섞여 있다.
- **점수는 퇴사 확률이 아니라 우선 확인 순서를 나타낸다.** 이 설명을 결과 파일에 직접 넣는다(`요약` 시트, `개인결과` 시트 아래 안내, `산정기준` 시트). "퇴사 확률 N%", "N명이 나갈 것" 같은 표현을 쓰지 않는다.
- **퇴사 이력이나 검증 자료가 부족하면 예측 성능을 확인할 수 없다고 말한다.** 사건 수와 기준일이 하나뿐인 점을 함께 적는다. 이 문구는 결과 파일에도 들어간다.
- **위험 점수와 인재 유지 우선순위를 합치지 않는다.** 위험 점수는 "누구부터 살펴볼까"만 나타낸다. 핵심 인재 여부, 성과 가치, 대체 가능성 같은 유지 우선순위 판단은 점수에 넣지 않고, 점수와 합친 종합 순위·등급도 만들지 않는다. 누구를 붙잡을지는 위험 점수와 별도로 HR이 판단하며, 스킬은 그 제안을 하지 않는다. 평가 이력은 "하락·정체"라는 변화 신호로만 쓰고 사람의 가치를 매기는 데 쓰지 않는다.
- **퇴사라벨에 맞춰 가중치·경계를 고치지 않는다.** 퇴사 건수가 적어 우연에 맞추게 된다. 검증 결과가 기대와 달라도 설정을 바꾸는 근거로 삼지 않고, 그대로 보고한다. 설정을 바꿀 때는 이유를 사용자와 정하고 `config/risk_config.json`만 고친다.

## 사용자에게 전할 내용

실행이 끝나면 다음을 순서대로 전한다. 개인을 특정할 수 있는 정보는 넣지 않는다.

1. **요약 3줄**(콘솔 출력 그대로)
2. **파일 위치**: 결과 파일과 ID 매핑 파일. 매핑 파일은 HR만 보관해야 함을 한 줄로 알린다.
3. **데이터 점검 경고**: 판단불가 건수, 제외한 기준일 이후 행 수.
4. **판단 근거 보는 법**: `개인결과`의 `판단 근거`·`추가 확인 사항`, `산정기준` 시트(가중치와 계산 방식).
5. **분석의 한계**: 점수는 퇴사 확률이 아님, 예측 성능 확인 불가(사건 수·기준일 1개), 입력에 없는 사정은 반영 못 함.
6. `검증` 시트에서 눈에 띄는 점이 있으면(예: 신호가 퇴사자 쪽에서 더 많이 나타나지 않음) 과장 없이 그대로 전한다.

## 설정 바꾸기

`config/risk_config.json`에 모두 모여 있다. 키 의미와 바꿀 때 주의할 점은 `references/scoring_and_validation.md`에 있다. 설정을 바꾸면 `산정기준` 시트에 바뀐 값이 반영되므로 결과 파일만 봐도 어떤 기준이었는지 알 수 있다.

## 참고 문서

- `references/input_spec.md` — 입력 시트·열, 기준일 정하는 법, 누락·중복 처리 표
- `references/scoring_and_validation.md` — 신호별 계산, 가중치, 등급, 기준일 이후 정보 제외, 검증 기준과 한계
- `references/output_spec.md` — 결과·매핑 파일의 시트와 열, 요약 3줄 형식
